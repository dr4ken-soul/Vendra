# Demo film

A 100-second film about Vendra, built with Remotion from a **real captured API
response**.

```
demo/
  DIRECTION.md            the direction: intent, category, palette, beats
  src/
    theme.ts              design tokens, read out of the product's CSS
    data.ts                GENERATED from a real recall response
    film.tsx               the composition
    Root.tsx               composition registration
  analysis/
    reference-analysis.md  six references measured, three deconstructed
    onsets.mjs             spectral-flux onset detection
    recall-response.json   a captured response from the deployed product
    build-film-data.mjs    generates src/data.ts from the captured response
```

## Render

```bash
cd demo
npm install
npm run render        # out/vendra-demo.mp4, 1920x1080, 100s, 30fps
```

## The rule that governs this film

**No string in the film was written for the film.**

`src/data.ts` is generated by `analysis/build-film-data.mjs` from
`analysis/recall-response.json`, which is an actual response from
`POST /api/assistant/recall` against the deployed product. The answer, the
sentence splits, the source numbering, the event ids, the dates, the totals and
the model name are all copied out of that response. If the system answers
differently tomorrow, the film changes tomorrow.

The same applies to the palette and the type. Ground `#f4f6f4`, ink `#242a27`,
accent `#b9402e`, success `#2f7654`, Barlow and Azeret Mono, and the easing curve
are read out of `web/src/app/globals.css` and `web/src/app/layout.tsx`. A film
that recoloured the product would advertise a version of it that does not exist.

## Regenerating after a change to the shop

```bash
cd web
node scripts/ask-demo.mjs demo.shop@vendra-demo.test <password> "<question>"
cd ../demo/analysis && node build-film-data.mjs
```

## What the film does not claim

Stated because the brief requires honest limits and the Ebbryn reference models
it — that film puts "this plan didn't pass" in the cut rather than hiding it.

- **One shop.** The film is not evidence of three users and is not presented as
  such. The shop it shows is an account created to build the film.
- **Recorded by the founder**, not by a third party.
- **A retailer cannot backdate an event.** The events API sets `occurred_at`
  server-side, so the deal date is 2026-09-30 while most event timestamps are the
  day the film was made. The film therefore claims the deal date, which is real,
  and does not claim "recorded days ago and recalled today", which the product
  cannot produce through normal use.
- **The interface is re-rendered** in the product's own design system rather than
  captured as screen footage. Every value in those frames is real; the frames are
  not pixels of the live site. Adding real capture is the next step.
- **No audio.** The reference library's music is not reused and none was written,
  so the skill's rule that cuts land on musical transients is unmet. The film is
  silent. See *Outstanding* below.
- Walrus deletion is unverified and the product reports that layer as blocked.

## Outstanding

- **Real screen capture.** Following the Ebbryn reference properly means the
  imagery is the product being used, cursor visible. The browser tooling was
  unreliable during the first pass and capture was not completed.
- **Audio.** No track, so the film does not meet the skill's timing requirement.
  A track at a known BPM is needed before cuts can be locked to bar lines.
- **Easing and transition behaviour** in the references remains unmeasured.
  Only stills were analysed.
- Three of six references were deconstructed; the other three were measured for
  duration, resolution and codec only.
